# Beta tools

Database migration and `dynamic-endpoint` backend deployed October 28, 2026. Web deployment runs on the associated main-branch push. Deployment order: apply `202610280001_beta_tools.sql`, deploy `dynamic-endpoint`, then deploy the web build. A new native build is needed for bundled iPhone clients.

- Send beta feedback is available directly from navigation. Help, feedback & settings also includes beta feedback and push preferences. The bell also opens push preferences. Feedback includes an explicitly disclosed device user agent, platform, version/build (native) or source revision (web), and page path without query strings/fragments. Admin → Beta feedback shows the latest 200 entries and supports new/reviewed/resolved states. No screenshot upload or external telemetry is added.
- Saved posts & resources is private per account, survives reload and works across devices. Only identifiers are stored. The list resolves content through the normal authorized endpoints, so deleted, blocked, or otherwise inaccessible items show an unavailable state and can be removed. Account deletion cascades through all three new member-tool tables.
- The existing welcome guide now includes directory and conversation actions, and supports account-persisted dismissal in either layout. Profile and membership completion use existing data. The directory action marks the visit in account metadata, not proof of a connection. A conversation with a message counts as started.
- Push controls cover direct messages, ministry events, and moderation reports (shown to administrators). Replies/reactions currently have no push sender and are not advertised as working push options. OS permissions remain separate.
- Superadmins can create optional 6–64-character case-sensitive shared codes, see expiry and signup counts, and revoke codes. Existing random links remain valid. Counts start with this migration, count committed account creations, and do not imply email verification. Existing `fmci26` gets a recognizable label. Revoked links remain in the activity list.
- Feed uses `/feed?limit=20&cursor=...`, returning `{items,nextCursor}` with mixed post/event/article entries. Normal visibility checks run before pagination. New arrivals wait for refresh. The existing collection endpoints remain compatible. Storage still reads complete collections; this is response/rendering pagination, not a database storage migration.
- Group and resource detail URLs work from both search surfaces and support browser history. Search has cached data, loading, partial-failure and retry states. Resource refresh failures retain loaded content. Search focus stays inside its dialog and restores on close.

Verification: tests cover per-user saved-item constraints, admin denials, preference validation, feedback limits/redaction, stable mixed-feed pagination and filters. The migration was also tested against the linked database inside a transaction that rolled back, checking invitation counts, revocation, credential removal and deletion cascade. No production schema changes were retained by that test.
